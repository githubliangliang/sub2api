# 设计与适配决策

按v0.2.12完整PR终态手工适配，保留本fork已落0.2.11实现。

- S01采用Lua原子计数与比较删除，计数key绑定主key TTL；发送新验证码时重置计数，不能通过写回旧JSON覆盖新状态。EmailCache接口改变要检索本fork全部实现、嵌入和mock。通知邮箱成功删除时机沿既有调用链，不机械套用普通邮箱回调。
- S01缓存只存摘要；旧明文token不兼容回退，升级后旧链接失效需重申请。原子消费先于密码更新，后续更新失败仍不可重复使用已消费token，申请新链接恢复。对Redis或Lua失败按无效token拒绝，验证miniredis及并发race。
- S02用户选择后从第三档提升，范围为账号表格既有priority编辑能力的快捷入口。450ms合并按钮操作；直接输入限制1–9999、Enter/blur提交、Esc恢复。异步请求绑定固定账号，失败恢复服务器值；卸载只发送已安排的待保存修改一次。避免空字符串/非数字被静默变成非法priority，验证卸载/快速翻页。
- S03用户选择后从第三档提升，复用Ent排序且在分页前执行。名称而非分组ID排序，NULL最后，ID同向次排序，用户隔离/过滤不变。源SQLite测试helper已在本地，不需要PostgreSQL迁移。

## 数据与范围边界

不改schema、历史迁移、锁文件、VERSION或菜单结构。支付两PR、TypeSafe原生平台与axios独立升级不引入。测试首先证明目标缺口，再验证正常路径与反例；后端全量unit/build、相关race与SQLite使用记录去重，前端typecheck/lint及真实组件测试在实施验收中记录。

## 实施适配（2026-10-02）

S01增加旧缓存兼容：旧验证码只有JSON Attempts而无辅助counter时，Lua在同一原子操作内继承已用次数，避免升级放宽猜测上限。新回归先失败再通过。SMTP测试记录真实邮件内容，验证实际链接对应的缓存摘要及重发失效；AuthService实际改密消费者亦验证只更新一次。

S02在上游组件基础上拒绝混合文本/小数/指数输入，加入账号ID与请求代次隔离。待保存修改在行复用时发往原账号；旧响应及卸载后的响应不更新新行。新增生命周期用例先暴露错误账号写入和旧响应覆盖，再验证修复。

S03来源KeysView测试夹带未采用的selectedKeys批量选择前置，只去掉该不适用断言；保留名称排序、参数、筛选、分页重置及SQLite跨页隔离用例，不引入批量功能。
