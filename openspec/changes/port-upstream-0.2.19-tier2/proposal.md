# Proposal

## Why

Grok原生返回和缓冲转换丢响应模型审计，目录解析及旧表单能覆盖受管成功快照；图片被截断、已启用搜索配置在保存中丢失，Gemini原生目录与映射口径不同。当前x/net存在可测的HTML平方复杂度。

## What Changes

完成六项独立行为，Grok两个簇共用同一完整PR来源；手工适配SQLite事务/单键CAS、当前frontend与模型接口，而不是带入整份PG、新诊断/授权/模型系统。

- S01：原生Responses返回原文审计字段，Chat/Messages缓冲路径保留固定大小前序模型及冲突位。
- S02：现有手动/后台统一严格解析及成功/失败观测，SQLite单键CAS/有界重读，普通编辑只采用数据库最新受管状态。
- S03：OpenAI按原20MiB单part边界明确拒绝超限，Grok在现有总body边界内完整解析或明确失败。
- S04：仅合并现有Web Search特定key的平台维度，现有前端保存者显式写入已支持平台true/false并支持清除。
- S05：全部账号声明映射时列表/详情与既有/v1/models同源，普通连接测试及已有默认目录更新，按本地custom list规则过滤。
- S06：以x/net0.62.0和量测的最小MVS图修复已有HTML平方复杂度，不覆盖整份上游mod。

## Impact

既有网关、usage与相关管理/模型消费者。测试使用本地HTTP夹具、临时SQLite及miniredis；评估probe只证明当前行为，实施前须增加预期新行为的失败回归。

第一/二档不新增schema或迁移；不引入受限管理员密钥、图片新计量开关、诊断大界面、新平台/新模型目录。用户选定Terra单独立项。保持个人范围与既有权限，支付、发布/tag/push/部署另属授权范围。
