# Proposal

## Why

Grok目录观测、乱序保护和SQLite CAS已经实现，但管理员仍无法直接区分目录是否过期、来源是否已变、映射是否出现在可信目录中。用户已明确选择补入诊断。

## What Changes

- 基于已保存账号与观测生成只读诊断：unknown/fresh/stale/source_changed、最近成功/尝试、目录与映射比较。
- 在既有管理端账号详情和同步结果提供诊断；同步后读取最新已保存状态。
- 在实际账号编辑页展示诊断、差异、同步/失败/配置回退信息和未保存提示。
- 保留请求乱序、账号切换、卸载和时间过期边界。

## Impact

复用既有Grok观察与同步链路，无新DDL、依赖、平台或DI服务。诊断本身不获取token、不发送HTTP、不写账号或修改路由；读取不会扩散到列表、调度或公共接口。模型参考价格改动保留。
