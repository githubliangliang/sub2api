# Design

## Context

现有账户extra中的Grok观察保存最近成功目录和最近尝试，按scope及开始时间管理并由SQLite CAS保护。本次在该基础上生成只读诊断。

## Decisions

1. 使用现有Grok模型URL验证与scope合同，诊断计算不获取凭据或请求上游，不修改观察/路由。
2. 只有同源、新鲜、可信文本目录才能报告not_listed。stale/来源变化/unknown保留历史展示，不声称当前缺失；已列入也不保证实际调用成功。
3. 通配符、空目标和裸动态别名不可确定；媒体/语音能力不以文本目录否定，别名解析不能用响应审计的更宽归一化替代。
4. 管理端详情返回可选字段，同步后读取最新账号再计算；列表/公共mapper/调度不计算诊断。
5. 前端显示已保存配置。未保存编辑不隐式覆盖诊断基线；同步使用已保存凭据，结果不能覆盖表单编辑。失败保留最近可信结果并显示刷新失败，configured_fallback不标为上游发现成功。
6. 账号切换、关闭和卸载使旧请求失效；新鲜结果随时间进入历史状态。面板ID唯一，长模型名和端点在移动屏幕内换行。

## Verification

实际SQLite/admin HTTP验证只读与同步后新状态，组件正反例和浏览器保存/重开/失败/账号切换检查。保持迁移227、依赖、生成代码及已有参考价格行为。
