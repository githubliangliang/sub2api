# 六项能力设计

## Context

用户选择的是六项可用功能，当前阶段只交付规格。现有实现已具备使用日志耗时、lite 账号列表、按模型限流、Anthropic 搜索模拟及固定128的转换下限。需要沿用这些生产消费者，并保留个人单节点约束。来源和具体 patch sites 分别见 source-baseline 与补充 PORTING。

## Goals / Non-Goals

目标：每项都有明确默认值、输入/错误边界、配置回显及验收场景；共享账号表单和网关文件按最终组合验收。

非目标：运维 TPS 分位数、账号筛选布局重做、新平台/模型、生图开关扩围、共享调度缓存、数据库迁移、依赖升级、支付和业务部署。

## Decisions

### D01 使用日志 TPS 由已有数据派生

使用 `output_tokens × 1000 / duration_ms`，保留一位小数；包含 TTFT，推理 Token 不再额外相加。默认随现有延迟列显示，尊重管理员和用户各自列偏好。数值缺失、非有限、非正值、图片输出、图片计费、Live/未知类型返回 `—`。历史缺少 request_type 的记录允许按其余条件计算。图片输入、文本输出记录仍可计算。

沿用 API/数据库已有字段，不增加 TPS 持久列、排序或导出字段，不引入同 PR 的运维百分位查询。

### D02 筛选仅持久化平台和状态

浏览器同源存储仅保存 `{platform,status}`，平台与状态分别按本地当前选项校验；一个字段非法不影响另一个。第一次请求前加载，切换/清空时保存，并保留原有回第一页、清理选择、排序/ETag/刷新流程。存储不可用时采用内存状态，读写失败不得阻断页面。搜索、分组、隐私、页码和选择项不新增持久化。

上游平台清单不是本地依赖，使用现有界面和后端支持的平台集合。

### D03 运维账号名通过现有 lite 列表补齐

主明细请求先返回，账号名后台补齐。成功记录、失败记录、桌面表格与移动卡片使用同一 ID→name 语义；已删除/不可见账号显示 `#ID`，无合法账号 ID 显示 `-`。

复用不带 credentials 的 lite 列表，禁用调度评分聚合。分页必须有终止条件；并发打开复用正在进行的名称请求。名称缓存使用有限有效期，手动刷新重建，缺项至多追加一次刷新；跨登录会话清理或按会话隔离。失败不缓存成永久空成功；取消/关闭和迟到响应不能更新新一轮视图。名称是当前账号名，不承诺历史名称快照。

不为显示名称扩展公开 API、后端 JOIN 或增加单条详情的逐行请求。

2026-10-25 最终调用链复核发现 `/admin/ops` 在个人精简中已下线，详情组件只有未挂载的 `OpsDashboard` 消费者。用户明确选择恢复完整运维页，因此恢复已有页面的管理员路由、侧栏和菜单管理入口；standard/simple 均可访问，侧栏继续受运维开关和隐藏菜单配置控制。已有后端运维 API、SQLite 查询、聚合/采集默认开关和其他页面限制保持原行为，不新增运维输出 TPS 分位数。

### D04 scope 明确表达隔离粒度

规则字段使用 `scope: account|model`。新建规则默认 model；编辑旧规则时回显等价默认：非401为 model，401为 account。运行时模型未知时无法精确隔离，使用原账号级/认证处理。旧字段缺失、非法或空字符串按缺省解析，打开再保存不能改变有效行为。

模型级写入已有账号模型限流状态，不设置账号全局暂停或全局运行时熔断；账号级沿用既有暂停和通知/缓存路径。首条匹配规则决定范围，失败不得跳到后续规则扩大或缩小作用范围。模型名按既有真实上游映射和调度键归一，保持 Antigravity 图片/文本隔离及 Grok 已有团队模型键规则。

401 只有显式 model 且已知模型、错误并非凭据失效时可模型隔离。OAuth、SetupToken/影子账号和明确 token_invalidated/token_revoked/Unauthorized 等凭据错误保留已有刷新/停号/换号策略，不受 model 覆盖。现有池模式、错误码开关、真实限额和内置 model_not_found 策略的优先级需按当前消费者逐项验证，不能套用不存在的平台链。

模型状态写入失败仅使本次按原预算换号并记录失败，不升级为账号全局暂停；不承诺写入失败后跨请求仍然记住冷却。清理/过期继续沿用现有机制，无新后台服务。

### D05 搜索模拟共享现有能力并保持启用边界

适用 `platform=openai` 且 `type=apikey` 的 `/v1/messages`。搜索管理器可用、全局启用、请求恰有一个受支持搜索工具，并且账号/渠道允许时才拦截。账号三态沿用 default/enabled/disabled；true→enabled，false→default。enabled 仍受全局开关约束，disabled 优先，default 使用当前分组渠道的 openai 标志。

本地渠道 UI 仅保存 Anthropic 标志，因此创建/编辑账号、渠道 OpenAI 开关的最小适配一并列入，避免不可配置的继承行为。simple mode 可使用现有全局配置与账号 enabled，不要求打开隐藏的渠道/运维菜单。

在原生 Responses 或 Chat 转换之前调用现有搜索服务，从最后一条用户消息提取查询；返回完整 Anthropic JSON/SSE。仅调用搜索提供商，不再访问所选 LLM 上游；不把结果长度伪造为模型消耗。保留搜索提供商自身额度/代理逻辑及既有网关使用量记录语义。OAuth/SetupToken/影子账号、其他入口、混合工具沿原处理。

空查询、搜索错误、代理不可用、写失败和取消不得输出伪成功；遵守输出前可换号、输出后不可重放，释放并发槽/串行锁，并保留本次请求的真实归属快照。验收使用本地提供商桩，不调用真实收费搜索服务。

### D06 输出下限作为服务配置显式传递

`gateway.min_output_tokens` 默认128，合法值为至少16的整数，支持既有 YAML/`GATEWAY_MIN_OUTPUT_TOKENS` 配置链；非法显式值在启动校验中报字段级错误。配置示例和个人模板保留默认128。程序内 nil/未初始化配置以及旧转换函数保持默认128，避免破坏现有调用者和测试夹具。

既有 Chat→Responses、Anthropic→Responses 和 Anthropic→Chat 转换对显式正数上限使用 `max(请求值,配置下限)`。未指定/非正值继续已有省略或输入校验规则。请求同时包含两种上限时保留原优先级，不增加实际输出 Token 保证。

本地已有 HTTP/SSE 消息转换消费者传递所属服务的配置。测得上游 legacy messages→Responses 入口文件222行的基座在本地缺失；本地同名兼容 helper 只处理OAuth搜索历史声明，因此不移植该新入口或为原生WS强行接入转换。原生 Responses input/显式 max_output_tokens、compact、WS首帧与后续response.create及原样转发保持原有语义。保留 Ollama 等提供商上限约束及原生 Claude Code 探针，不全局改写所有 max_tokens 字段。不使用可变包级配置，保证两个服务实例的设置互不污染。

## Risks / Trade-offs

- 旧规则兼容及401优先级是F04主要风险，必须覆盖真实凭据失效和非凭据模型错误的反例。
- F03 名称查询可能耗时或失败，主明细不能依赖它；选择有限缓存而非无限持有账号名。
- F05 会在输出前改变请求分流，必须验证所选账号身份、开关、并发释放和真实 handler 记录，不能只测 helper。
- F06 的多入口配置容易漏接，需先列调用图，再核对 HTTP 与 WS 多轮反例；禁止为缺失平台或缺失的legacy消息入口补完整子系统。
- F01 是含首字等待的平均速率，不等同于仅生成阶段速度；界面提示必须明确。

## Migration Plan

预计复用现有 credentials/extra JSON、模型限流记录及浏览器存储，不新增 schema/迁移。旧规则在运行时按缺省解析，无批量回填。部署后缺省配置保持128；可回退新代码并继续读取原 JSON。若实施测出必须改变 schema，应先修订设计并按实际最大迁移号分配，不能改动226及以前文件。

## Open Questions

无阻塞规格问题。实施时需要量测的内容限于现有生产调用图、名称缓存实现和测试覆盖；不能因此扩大六项行为范围。运维 TPS 分位数需另行选定。
