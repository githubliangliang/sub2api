# 设计与边界

以现有路由、账号、配置和SQLite写入链为基座，按行为适配。优先完成认证/数据一致性和Claude/Codex/Grok协议问题，再处理相关UI及有测量依据的热点维护。

每次attempt/WS轮次独立观察上游模型、用量和错误；先观察原文再还原公开模型。keepalive不等同于语义输出，但HTTP已提交时错误必须继续为SSE。首输出暂存有界，取消、预算、槽位和会话租约只有一个释放责任。

SQLite事务覆盖一次操作的所有清空、删除和写入；旧TEXT时间与DATETIME扫描保持兼容，固定quota窗口、软删除和usage去重不被重做。不复制PG-only SQL或新增无消费者迁移。

- S01：只用既有5m/1h列；不导入30m/12h字段、迁移或未选价格策略；自定义0/Fast保留。
- S02：比对实际发送token；不在401路径刷新/持久化凭据，不绕过重试上限或正常401策略。
- S03：不得复制PG ANY/ALL/unnest/强制类型转换；不更改历史迁移或用户固定quota。
- S04：前奏需沿用8MiB有界暂存，不能原样引入无界strings.Builder；私有账号头不得提前泄露。
- S05：保留配置的idle默认及既有模型冷却；不要把惩罚扩散到整个池。
- S06：不剥离声明ID、不改普通工具身份；不导入完整账号命名空间或ojson基座。
- S07：仅Grok启用prefix规则；不引入通用工具桥或新搜索平台。
- S08：先观察原文再还原公开名；保留本地价格来源准入及已解析Fast tier，不为模型修复重做tier基座。
- S09：先观测后改名；不得替换正文/工具参数中的同名字符串，不影响非Composite响应。
- S10：保留上一轮合成none/最终校验和GLM通用兼容；不复制缺失原生平台闸门。
- S11：请求内容错误不换号；只模型冷却，沿用现有显式规则及SQLite单键更新。
- S12：无ID的字符串快照与新相同调用不可区分时采用来源保守策略，不猜造调用。
- S13：采用responseJsonSchema，不扩展Gemini新模型或cache CRUD；保留资源限制。
- S14：保留既有timeout默认，不导入Carbon等模型和完整新thinking策略；绑定检查需防并发误删。
- S15：不按发布摘要删除ForceCacheBilling；两个微提交必须以最终PR状态解释。
- S16：不随行#8833的20s stale grace或合并回源；保留revision/retire/单节点缓存契约。
- S17：不引入新quota-summary或恢复监控v2整页；缺失Spark专用前置不作为依赖导入。
- S18：只增DTO字段，无新DB列；user API/UI不能泄露账号成本；保持model_source等维度。
- S19：不能只加无管理goroutine；不改变已有目录实际正文hash和零覆盖优先级。
- S20：30秒是来源参数推算，不是本次实测断线耗时；应用层120s idle保留。
- S21：不能把来源约899行parser整体覆盖本地窄sanitizer；需测实际适配规模和编辑重叠。
- S22：补转义回退；不导入DeepSeek缺失placeholder消费者、无管理的懒日志全body保活、#8816账务lane或完整COW。
- S23：不升级库版本、上游PG依赖、fork VERSION或历史记录；codegen/CI尚不是本轮已验收项。
