## ADDED Requirements

### Requirement: 调度准入失败必须给出具体原因
系统 SHALL 让 OpenAI 兼容账号的调度准入判定返回**第一个否决点的具体名称**，而不只是布尔值。
原因 MUST 覆盖至少：账号为空、平台不匹配、账号整体不可调度、按模型限流、
按配额自动暂停（并带上触发的窗口）、模型不支持、端点能力不匹配、compaction 不支持、
以及分组利润控制否决。空字符串 MUST 表示通过。

#### Scenario: 账号被按模型限流
- **WHEN** 账号整体可调度，但对本次请求的模型处于限流状态
- **THEN** 原因 MUST 为「按模型限流」而不是「整体不可调度」
- **THEN** 两者 MUST 可区分

#### Scenario: 账号整体不可调度
- **WHEN** 账号本身不可调度
- **THEN** 原因 MUST 为「整体不可调度」

#### Scenario: 配额自动暂停
- **WHEN** 账号因配额利用率触发自动暂停
- **THEN** 原因 MUST 带上触发的窗口标识
- **THEN** 窗口为空时 MUST 回落到不带窗口的通用原因

#### Scenario: 平台不匹配
- **WHEN** 账号平台与请求平台不一致，或账号不是 OpenAI 兼容类型
- **THEN** 原因 MUST 为「平台不匹配」

#### Scenario: 利润控制否决
- **WHEN** 前置的普通调度门全部通过，但分组利润控制否决该账号
- **THEN** 原因 MUST 为利润控制给出的具体原因
- **THEN** MUST NOT 被更早的门覆盖掉

#### Scenario: 准入通过
- **WHEN** 账号满足全部条件
- **THEN** 原因 MUST 为空字符串

### Requirement: 诊断能力 MUST NOT 改变准入行为
本能力是纯可观测性增量。原有的布尔判定 MUST 保留为「原因为空」的薄包装，
短路顺序与判定结果 MUST 与改动前逐个一致。诊断原因 MUST 只用于服务端诊断，
MUST NOT 进入客户端响应体。

#### Scenario: 同一账号集合的选择结果
- **WHEN** 用同一批账号、同一请求参数走调度
- **THEN** 选中的账号 MUST 与改动前完全一致
- **THEN** 被排除的账号集合 MUST 与改动前完全一致

#### Scenario: 门的短路顺序
- **WHEN** 一个账号同时违反多个条件
- **THEN** 返回的原因 MUST 是**最先**被触发的那个门
- **THEN** 后续门 MUST NOT 被求值（保持原有短路语义）

#### Scenario: 原因不外泄
- **WHEN** 因无可用账号而返回错误给客户端
- **THEN** 客户端响应 MUST NOT 包含账号级的内部否决原因
