# 用量日志记录请求和实际转发的推理强度

## Why

客户端请求 `xhigh`、分组上限降为 `high` 时，当前一条用量记录只有一个推理强度字段。管理员无法从该记录区分客户端的选择、分组改写或模型族归一化。在同一 WebSocket 连接连续请求不同档位时尤其难排查。

## What Changes

在请求进入策略处理前记录客户端声明的强度，并沿现有转发结果保存本轮实际发出的强度。普通用户在用量页及导出中看到请求值；历史记录及未捕获请求值的记录沿用已有显示。管理员可在请求值与转发值有差异时同时看到两者。

## Capabilities

- 新增 `usage-reasoning-effort`。

## Impact

涉及既有 HTTP、SSE、WebSocket 用量记录、SQLite 读写、用户和管理员 API、页面及导出。增加一个可空文本列。分组上限、模型支持范围、Fast 档位和计费策略继续由既有逻辑决定。本提案可独立于透传筛选实施。
