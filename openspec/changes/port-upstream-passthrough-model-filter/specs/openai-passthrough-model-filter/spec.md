## ADDED Requirements

### Requirement: P1 透传账号按来源模型选择
网关 SHALL 仅在 OpenAI 透传账号显式开启模型筛选且映射非空时，按来源键限制该账号的候选资格。

#### Scenario: 精确键、通配键和映射目标
- **WHEN** 账号 A 配置 `alpha → vendor-only` 及 `beta-* → target`，账号 B 可以处理 `gamma`
- **THEN** A 可接收 `alpha` 和 `beta-1`；仅作为目标的 `vendor-only`、`target` 均不能据此选中 A；请求 `gamma` 可选 B。

#### Scenario: 存量账号和空规则
- **WHEN** 透传账号的筛选字段缺失、为 false、为字符串 true，或筛选已开启但映射为空
- **THEN** 该账号沿用透传的宽松模型资格；其它分组、端点和模型退休限制仍然生效。

#### Scenario: 普通账号
- **WHEN** 非透传账号留有筛选字段并配置模型映射
- **THEN** 账号沿用原有的映射和转发目标规则。

### Requirement: P2 调度快照与转发保持一致
网关 SHALL 在完整账号、调度快照及粘性候选上执行同一筛选，并保持既有透传正文语义。

#### Scenario: 旧粘性绑定与快照更新
- **WHEN** 某模型曾粘在 A，管理员开启筛选并从规则中移除该模型，更新已进入调度快照
- **THEN** 此后按该模型选择时，完整账号或快照均排除 A，并按现有规则选择其余候选；若无候选则走已有错误处理。

#### Scenario: 匹配后的请求
- **WHEN** 透传请求模型为 `alpha`，来源键匹配且目标值为 `vendor-only`
- **THEN** 匹配后仍按原透传路径发送 `alpha`；开关本身不改写正文、工具或流式参数。

### Requirement: P3 模型目录反映可用来源名
系统 SHALL 在普通模型列表和 Codex 目录中按账号资格呈现具体来源模型名，并保留各目录已有的分组和元数据约束。

#### Scenario: 混合账号与残留映射
- **WHEN** 同组内有已开启筛选的账号和不受限的透传账号，后者留有旧映射
- **THEN** 两者贡献的可用模型取并集；旧映射不会缩小不受限账号的缺省目录，映射目标与通配模式自身也不会被当成该筛选账号提供的模型公开。

#### Scenario: 原始目录与分组缓存
- **WHEN** 同一上游原始目录被不同分组复用，或者客户端带着修改规则前的 ETag 重新查询
- **THEN** 每个响应只含该视图可见的具体条目，保留其名称与元数据；只有最终正文一致时才可返回 304，其他视图仍能使用完整原始目录。

#### Scenario: 权威空结果
- **WHEN** 已取得的目录经过账号和分组筛选后没有任何匹配
- **THEN** 返回空目录，已有缺省发现流程仅用于未取得权威目录的情况。

### Requirement: P4 管理员可保存及批量修改筛选
管理界面 SHALL 在现有支持透传的账号创建、编辑和批量编辑流程中提供该筛选并保留无关设置。

#### Scenario: 保存、重开与关闭
- **WHEN** 管理员在支持透传的账号启用筛选、配置模型并保存，随后重开、关闭筛选或切换到另一个账号
- **THEN** 重开显示该账号已保存的开关与规则；关闭后恢复透传的宽松选路，切换账号时显示新账号的配置。

#### Scenario: 批量修改其它字段
- **WHEN** 批量操作只勾选优先级等其他属性，或显式勾选透传配置并应用筛选
- **THEN** 前者保留每个账号原有筛选；后者仅修改选定账号及选定字段，并保留其他凭据和配置。
