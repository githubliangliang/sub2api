# 设计

## 账号资格与透传

`accounts.extra.openai_passthrough_model_filter` 只有布尔值 `true` 且账号已经启用 OpenAI 透传时才生效。现有透传开关继续识别历史 OAuth 配置。筛选启用且映射非空时使用现有匹配器检查请求模型是否匹配来源键；空映射表示没有账号级限制。普通非透传账号仍按原规则解析映射目标。

把开关与现有模型映射一起纳入调度快照。按模型命中、粘性账号复选及重选都在发起上游请求前应用同一条件。过滤仅改变可选账号集合。验收用相同透传输入和不同映射目标对比上游实际收到的模型名、请求体与既有传输处理。

## 目录

分组列表取各合格账号可见模型的并集，再应用分组、端点和退休规则。旧透传账号残留的映射不能代表其服务范围；组内另有不受限账号时保留已有缺省模型。宽松账号与筛选账号混合时，一个账号的过滤也不能抹掉另一个账号提供的模型。

对已经取得的 Codex 或普通上游目录，按真实模型 ID 筛选，保留条目的元数据。通配规则只能匹配具体 ID。分组配置目录继续沿现有优先级处理；筛选后确实为空时，保持权威空列表，避免回填全部默认模型。共享缓存保留原始目录，对账号及分组的最终视图计算客户端 ETag。账号或规则变更后，让相关分组列表和调度快照按现有更新机制失效。

## 管理操作

创建和编辑时，仅在透传开启后提供二级开关；开启后可编辑已有模型规则。旧配置中的其他 `extra` 和凭据字段需随部分更新保留。批量编辑沿用字段选择语义。切换账号、关闭开关及重新打开弹窗均从该账号的持久化配置恢复。
