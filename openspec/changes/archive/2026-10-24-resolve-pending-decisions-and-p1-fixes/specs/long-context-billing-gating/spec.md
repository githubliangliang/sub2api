## ADDED Requirements

### Requirement: 长上下文阶梯以分组开关为统一入口，账号开关只能额外开启
系统 SHALL 把分组的长上下文定价开关作为唯一入口：分组开着即适用长上下文阶梯。
账号侧的 API 开关 MUST 只能**额外开启**（为真时把结果置为开），MUST NOT 因为它为假就否决分组配置。
这与改动前的「两者都开才适用」相反。

#### Scenario: 分组开、账号关
- **WHEN** 分组长上下文定价开关为开，账号 API 开关为关
- **AND** 请求超过长上下文阈值
- **THEN** MUST 适用长上下文阶梯倍率
- **THEN** 这与改动前相反：改动前不适用

#### Scenario: 分组关、账号开
- **WHEN** 分组开关为关，账号 API 开关为开
- **THEN** MUST 适用长上下文阶梯倍率

#### Scenario: 两者都开
- **WHEN** 分组与账号开关都为开
- **THEN** MUST 适用，行为与改动前一致

#### Scenario: 两者都关
- **WHEN** 两个开关都为关
- **THEN** MUST NOT 适用，行为与改动前一致

#### Scenario: 账号开关未设置
- **WHEN** 请求未携带账号级开关（值缺失）
- **THEN** MUST 完全由分组开关决定

#### Scenario: 想保持旧行为的分组
- **WHEN** 运营方希望某分组不再被收长上下文倍率
- **THEN** 关掉该分组的长上下文定价开关 MUST 足以达到目的
- **THEN** MUST NOT 需要改代码

### Requirement: 区间定价的前置条件仍是 AND，不随开关组合放宽
系统 MUST 保持「仅在无区间定价时才应用长上下文阶梯」这一前置条件为 AND：
区间定价已自含上下文分层，再叠一层长上下文倍率会重复计价。
账号开关为真 MUST NOT 绕过这个前置条件。

#### Scenario: 存在区间定价且账号开关为开
- **WHEN** 解析出的定价包含区间定价
- **AND** 账号 API 开关为开
- **THEN** MUST NOT 额外应用长上下文阶梯倍率
- **THEN** 费用 MUST 完全由区间定价决定

#### Scenario: 存在区间定价且分组开关为开
- **WHEN** 解析出的定价包含区间定价，分组开关为开
- **THEN** MUST NOT 额外应用长上下文阶梯倍率

#### Scenario: 无区间定价
- **WHEN** 解析出的定价不含区间定价
- **THEN** 开关组合 MUST 按上一条 Requirement 决定是否适用阶梯

### Requirement: 无定价解析器的回退路径保持原语义
当计费入口拿不到定价解析器时，分组开关不可得，账号开关是唯一信号。
该回退路径 MUST 保持改动前的语义（账号开关直接决定），MUST NOT 一并改成 OR。

#### Scenario: 回退路径且账号开关为关
- **WHEN** 无解析器，账号开关为关
- **THEN** MUST NOT 适用长上下文阶梯
- **THEN** 行为 MUST 与改动前一致

#### Scenario: 回退路径且账号开关未设置
- **WHEN** 无解析器，账号开关值缺失
- **THEN** MUST 按改动前的默认（适用）处理
