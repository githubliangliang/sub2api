# Design

## SQLite 后台服务

删除按数据库种类统一跳过启动的判断。每个服务仍遵守自己的配置与依赖检查。逐项审查清理任务领取/进度/取消、账号到期更新与 outbox、定时计划及结果 SQL，不能仅因为 NOW() 字样认定不兼容：本 fork 已注册对应 SQLite 函数。

新启用的时间读取接受 modernc 返回的 time.Time、string 或 []byte；无时区字面量按 UTC 读取。过期与到期判断核对旧 RFC3339/SQLite 字面量的时间顺序。使用新回归确定需要修复的范围，不修改已应用的迁移。

周期任务保留有界执行、取消与现有并发上限；停止要取消等待/当前执行，不因重复启动或跨分钟重叠重复发起账号测试。清理只处理用户明确创建的任务；启用服务不自行创建全量删除任务。

## 操作日志清理

根因是仓储全量清理 SQL 使用 TRUNCATE。在 SQLite 上使用普通 DELETE，保留原有清理接口与同步留痕，保留自增序列。请求仍必须走管理员会话及现场 TOTP，不新增跳过验证或简单模式豁免。UI 保留确认 → TOTP → 清理 → 刷新，数据库回归与 handler/组件测试覆盖实际调用链。

## 轻量调度

#8249 只保存当前请求的分组 ID 快照与 sync.Once 探测，不添加进程级缓存。显式 true/false 标记均优先于探测。需要确认请求取消时不会将被取消的查询永久记成 false，并核对实际查询时间界限。

#8250 使用逐条目哈希及无序合并代替临时键列表排序。签名只用于进程内映射缓存失效，不是密码学哈希，也不写数据库；字符串与非字符串必须保持不同标记，同一 map 原地等长修改必须被发现。

## 验证与范围

先保存旧 SQL 的失败回归和优化前 benchmark，再实现并运行定向 SQLite、handler、race、后台生命周期与映射测试。最后完成后端 unit/build/lint、迁移和 quota 回归、前端测试/typecheck/lint/build/critical，回填验收与证据。

VERSION、依赖、Ent、Wire 生成代码及迁移保持基线；若事实证明必须变更，先明确测量理由，不将未测前置当作授权。业务实例数据、发布与部署不操作。
