# 设计与决策

1. 按行为手工移植或应用可验证的小补丁，保留本地同文件自有逻辑。PR 整体用于理解来源，不能覆盖整文件。
2. F01 不依赖未落的上游 quota classifier。直接修复本地 reset 判据与 fallback 开关，保留 Spark shadow 排除、明确配额 reset 和现有重试策略。
3. F02 区分请求模型、选号用上游模型、计费模型。仅改变选号输入，不让客户端响应模型名或成本口径意外改变。
4. F03 三层筛选必须使用同一渠道限制规则；只修最终转发会浪费选号与并发槽。
5. F07 按最终出站 UA 生成版本和指纹，messages 与 count_tokens 都要覆盖；后续第二档 CLI 版本开关再次联合验收。
6. F08 不放宽非 Claude UA 或普通请求验证。F09 必须按最终 beta header 决定 body 字段，不按模型名猜测权限。
7. F10 已知模型级故障即使持久化失败也不能升级为账号级冷却；真正的共享窗口耗尽仍按既有规则处理。
8. F12 使用指标专用 nullable helper，不改变其它业务字段的零值含义。
9. F13 只补约束合成的谓词。当前 API Key Responses 非透传路径可达；其它转发路径不做批量谓词替换。

每项可独立提交和回退。回退调度修复会恢复原有错误过滤/停调行为，验证报告应注明观察到的影响。
