## 9. 本轮通用教训

- “新合并”先与上次已经观察到的 main 比较，tag 后已知 VERSION 提交不能每轮重新计为增量。
- fetch 更新其他分支和 CLA 签署不代表产品已合并；用 main SHA、正式 Release 和实际 merged_at 交叉核验。
- 发布前 intake 的未实施措辞是历史快照；当前完成状态要追到实施提交、发布 tag 和冻结哈希。
- 没有新候选也应留下可审查的时间与来源证据，同时避免重复制造提案、四态统计或测试通过结论。
