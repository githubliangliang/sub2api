v1.1.24

个人 / 单节点 SQLite 版：完整整合 Fast、Free Fast、Ultrafast；移植上游 v0.2.20 第一档与第二档的既有网关修复，覆盖 Claude Code、Codex、Grok、Terra、资源边界和使用记录导出。

相对 v1.1.23（5c135c31dfbd6a1fcb701767f2f78933c4280aea）。产品基线为 a25ce7bedb3167e2b9244117893d6762e1a85a95；发布准备提交为本 tag 指向的提交，提交内 VERSION 为 1.1.24。发布时间：2026-11-11。
继续使用本 fork 自有 1.1.x 版本号，保持 SQLite-only、可选单进程 miniredis、simple mode、Go 1.27.3 和 WS 默认容量系数 1.0。SQLite 最大迁移由 227 升至 228，鉴权快照由上一版的 19 经 Fast 的 20 升至 21；依赖版本不变。

1) 历史 v0.2.19 及以前：用户选定 Fast / Free Fast / Ultrafast 完整能力

   实现提交：326513cdc68cc50d31e25a07ae98ecd6f5a3ca1f。
   来源固定于上游 v0.2.19，按 #6129/#6378/#6379/#6444/#6571/#5833/#7613/#7730/#7811 的相关行为整合。本项是用户明确选定的历史第三档能力；不代表历史版本全量移植。

   - OpenAI/Codex 的 fast 统一为 priority，ultrafast 可贯穿现有 Responses、HTTP 自动透传、Chat、Messages、Chat 后备转换和 WebSocket。非法档位在上游请求前拒绝，WS 按 response.create 的现有错误协议处理。
   - 系统加速策略支持 Ultrafast 与“未指定档位”。未配置规则时不主动升级请求；missing 仅在 force_priority 策略下注入，旧 all 规则不改变未指定档位请求。
   - 分组新增“强制 Fast”和“Free Fast”两个独立、默认关闭的开关。强制 Fast 将该分组 OpenAI 请求设为 priority，包括客户端原来的 ultrafast，随后继续执行全局过滤/拦截策略。
   - Free Fast 仅将 OpenAI priority 的用户实际费用按 Standard 重算，保留上游成本、费用明细和日志档位；不作用于 Ultrafast 或 Grok。它不表示上游免费，也不降低账号侧成本。
   - 分组逐模型与渠道模型定价支持 Fast 倍率覆盖，接受有限正数；清空恢复原有价卡策略，Ultrafast 仍独立结算。价格来自选定快照和本地配置，不是实时官方报价。
   - 公开 API 明确降档可降低计费，不因响应声称更高档位自动加价；Codex OAuth/setup-token 常见的 default 回显保留实际发出的 Fast 档位。WS 每轮分别观测，缺失/未知帧不污染已有值，下一轮不继承旧档位。
   - 目录遵循账号 metadata/raw catalog 声明及显式空列表。官方 Astra API 的 Ultrafast fallback 有限定范围，OAuth 套餐名称不会自动授予能力。
   - Claude 原生 speed=fast 沿用既有转发与日志语义并进入档位计价；Messages→OpenAI 的对应兼容路径可映射到 priority，原生 Claude 仍不因单独 beta header 推断 Fast。
   - SQLite 迁移228新增 groups.force_openai_fast、groups.free_openai_fast，默认 false；channel_model_pricing.fast_multiplier 可空且必须为正。分组复制、仓储、DTO、鉴权投影和配置页面贯通；Ent 已按 schema 生成。

升级与行为变化
==============

1. 数据库：SQLite迁移228会新增两个默认关闭的分组开关及可空渠道Fast倍率，旧迁移不改写。升级前保留数据库与配置备份；本次发布不会替用户操作业务数据库或部署实例。鉴权快照21拒绝旧结构并重建缓存。
2. 资源：默认SSE行上限由500MiB收紧到40MiB；实例入站预算新增64MiB。确实需要大图片/长请求的部署可按可用内存显式调大，仍需为数据库、响应、协议转换和GC留余量。
3. 预算不是总进程heap上限，也不是全部协议转换分配的精确计量器。受控503表示暂时容量不足，客户端可按Retry-After重试；独立单请求大小限制仍可返回413。
4. 断开后的drain到期可能只能记录已观测用量；不会无限等待最终usage或伪造完整结算数据。
5. Terra：API与Codex的effort标尺不同；minimal兼容请求改为400，OAuth/setup-token长上下文附加费豁免按最终发送模型判断。已配置账号metadata/raw catalog继续优先。
6. Fast：新分组开关默认关闭；Free Fast只影响用户费用，强制Fast会将原Ultrafast改成priority。simple mode既有页面权限不扩大，分组策略管理沿用standard模式入口。
7. 导出：遇429时会等待重试，离页或换号取消。Antigravity测试改为真实发送填写的prompt，并从1token提高到256输出预算，单次测试可能产生更多上游输出。
