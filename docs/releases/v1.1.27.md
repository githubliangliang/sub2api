历史选定条目 #8748 / #6188（本版新增）
--------------------------------------

本地实现提交：`d2488b1105f091b6fce4445395fec1835306fcf8`。

1. **#8748：OpenAI 透传账号可按来源模型筛选。** 仅在账号显式开启筛选且模型映射非空时，按映射的来源键限制候选，支持既有精确键和通配键；映射目标值不能使账号获得来源名资格。筛选缺省、关闭、非 boolean true 或映射为空时，继续采用原透传资格。非透传账号沿用既有映射语义。
2. **选路、快照、粘性与目录一致。** legacy/load-batch 调度及快照排除不匹配账号，过期粘性绑定按现有规则重选。通过筛选后仍按透传语义发送原模型，不因筛选改写正文。普通和 Codex 目录保留具体来源模型的元数据；混合账号按可用贡献合并，权威空结果不补默认模型，ETag 根据最终响应正文计算。
3. **创建、编辑和批量配置。** 支持透传的账号可保存、重开和关闭筛选；批量只修改勾选字段，保留其他凭据、映射和设置。v0.2.24 的 S06 进一步将“修改透传”和“修改过滤”拆成独立选择，见下文。
4. **#6188：区分请求和实际推理强度。** 在分组策略、模型映射及降级前采集客户端声明；协议显式值优先于原模型已知后缀，缺省保持为空，不用兼容桥默认值或映射目标后缀冒充请求值。保留本地 none/max 等已接受声明，同时记录成功转发的实际值。
5. **HTTP、SSE、WebSocket 与持久化。** 换号和异步结算保留同一请求的配对；WS 每轮分别捕获，连接复用和延迟写入不会串轮。例如请求 xhigh 被分组上限降为 high，记录为 xhigh→high。迁移 230 新增 `usage_logs.requested_reasoning_effort TEXT`，历史记录为 NULL，原实际强度、金额和去重身份保留；单条、批量、best-effort 写入及查询均支持。
6. **角色、页面及导出。** 用户读取请求强度，管理员可额外区分实际转发强度；仅有一个值或两个值相同时显示一个值，历史记录继续回退显示原实际值。管理员和用户的列表、详情、CSV/XLSX 导出遵守同一角色边界，用户导出不增加上游强度列。

升级与行为变化
==============

1. **数据库。** 从 v1.1.26 升级会执行 SQLite230，新增可空 requested_reasoning_effort 列。历史行请求值为 NULL，继续读取已有实际值；不回填或重算历史费用。请按既有升级流程备份 SQLite 数据和配置。
2. **输入拒绝。** 存在重复协议字段、转义等价字段或有歧义 multipart 声明的旧请求会更早失败，避免准入、改写、上游解析和计费各取不同值。调用方应只发送一份有效声明；用户自由键空间中合法的大小写不同键继续支持。
3. **透传。** 新筛选默认不启用；显式开启且映射非空后，来源模型不匹配的账号不再参与该请求。匹配后的透传原模型保持，批量透传和过滤可独立保存。
4. **推理强度。** 新记录能区分请求值与成功转发值；管理员可看到 xhigh→high 等差异，用户遵守自身 DTO 和导出边界。WS 逐轮记录，未声明的轮次不继承上一轮请求值。
5. **轮换与限流。** 已完成轮换的保存不因原请求取消而立即中止；CAS 仍保护并发重新授权。OpenAI 408 使用现有换号预算；裸 429 的限制只作用于同一请求内的重复冷却，不放宽明确限流规则。
6. **目录与页面。** 音频及自动 [1m] 声明可能因可路由候选缺乏共同能力而减少；这是目录保守性修复。Claude/Gemini 新快照会自动刷新，旧异步结果不覆盖新值；后台新建普通用户开始使用当前默认平台 quota。
7. **统计。** 模型平均 TPS 改为耗时加权，和此前数值可能不同；整窗口输出 TPS 的算术均值/分位数不变。Grok 明确成功搜索数 0 会覆盖 item fallback，非法值不会冒充合法计数。
8. **构建和资源。** Go1.27.4、auth21、现有依赖、Ent、64MiB gateway body 预算、40MiB SSE 行、8MiB 暂存/队列、120 秒读写 idle 和 WS 默认容量系数 1.0 保留。本版不把局部夹具峰值作为完整服务的生产容量承诺。
9. **发布准备标签更正。** 首轮 v1.1.27 标签在生成 Release 前被旧 integration 断言阻断；修正测试并通过完整集成后更新至最终发布提交。若已拉取该准备标签，需要同步最终 v1.1.27 引用；初轮对象及本地备份记录保留在发布跟进证据中。
