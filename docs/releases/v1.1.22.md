同步上游
========

1) 上游 v0.1.180：普通工具参数、custom 别名与 defer_loading 尾项（本 fork：becd2d2a3，2026-10-31）

   - C01，来源 e2d9ce0ca + fbc9ee626：Chat 兼容上游返回的普通 function-call 参数必须是合法 JSON，截断或非法参数不能被标为完成；回放历史中的坏调用与对应输出配套过滤，避免留下孤儿工具结果。
   - 保留合法 JSON、既有空参数默认、有效 length 终态及 custom 工具原始输入；兼容缓冲响应和流式终态，不把正常工具调用统一丢弃。
   - C02，来源 31d5b67ba：还原唯一、无歧义的 custom 工具别名。显式 function 声明和真实 namespace 归属优先，名称碰撞保持保守判断；HTTP、SSE 的 added/done/terminal 事件使用一致身份。
   - C03，来源 7a09a2eaf：依据最终发送的 tools 声明清理孤儿 defer_loading。只有真实内建 tool_search 才能保留该依赖标记，同名普通 function 不充当前置；通用 adapter 与 Grok 实际出站路径一致，声明源对象保持原内容。
   - 无效工具、断流和取消后的已观测用量仍沿现有异步写入路径保留；实际 HTTP、队列和 SQLite 验证余额、Key quota 与 usage_billing_dedup 只结算一次。

2) 上游 v0.2.5：Responses 事件序号尾项（#7129 / 25c21aedd，本 fork：becd2d2a3，2026-10-31）

   - C04：Responses 第一帧显式写出 sequence_number: 0；已有合法非零序号保持原值，本地合成事件从实际已写出的序号继续递增。
   - 覆盖 typed Responses、原生与 passthrough SSE、compact、handler 错误、bare error 和 WS HTTP bridge。未实际写出的 payload 不提前消耗序号，延迟错误继续当前流的顺序。
   - 严格 HTTP 消费者检查必填整数、首帧 0、已知非零值和递增序列；含非法数值及未写出事件的反例。
   - C01–C04 共 17/17 任务完成，见[历史客户端兼容验收](https://github.com/githubliangliang/sub2api/blob/v1.1.22/openspec/changes/archive/2026-11-01-port-upstream-historical-client-compatibility/verification.md)。这是旧工具桥和事件字段的选定尾项，不代表完整新工具平台或 Grok 调度机制全部纳入。

3) 上游 v0.2.19：用户选定 Grok 模型目录诊断（#8339 / 15701ba18，本 fork：becd2d2a3，2026-10-31）

   - 在已有目录观测、乱序保护和 SQLite CAS 上，增加 unknown/fresh/stale/source_changed 状态、最近成功与最近尝试、失败信息、来源变化及映射与目录差异。
   - 诊断使用已保存账号配置和现有纯映射解析器；读取本身不获取 token、不发送上游 HTTP、不写账号或填充映射缓存。仅在 Grok 管理详情和手动同步结果提供诊断，同步后读取最新已保存状态。
   - 目录过期、来源改变、旧格式或同步失败时保守展示；最近成功目录和失败尝试分开保留。别名、通配符及媒体模型有对应反例，目录“未列入”只描述可信缓存中的观察，不保证或否定模型可调用性。
   - 实际账号编辑页增加诊断面板、差异、同步结果、失败与配置回退提示。同步保留未保存的模型编辑；保存、重开、时间过期、账号切换、迟到请求、关闭和卸载均有保护。
   - 桌面和 390px 移动视口验收通过；12/12 任务完成，见[Grok 诊断验收](https://github.com/githubliangliang/sub2api/blob/v1.1.22/openspec/changes/archive/2026-11-01-port-upstream-0.2.19-grok-model-diagnostics/verification.md)。用户选定的第三档范围仅覆盖此诊断能力。

明确未合
========

- 支付、充值、购买/续费、退款、返利及支付提供商专属功能、配置、依赖和迁移继续排除。
- #7043 默认 WS 容量系数 5.0 已决定不采纳，继续使用 1.0。
- 渠道监控 Base URL 路径前缀、整窗口 TPS 分布、用量/费用趋势、Claude 重置 grant 查询/兑换、统一图片实际张数计量开关、50 MiB 上传扩围和 Gemini 重试配置仍按个人用途选择。
- Fast/Free Fast/Ultrafast、Realtime、完整 Grok 429/WS 容量与 exec_scope/抢占机制、动态长上下文/effort 计价、未选新模型及 Gemini/Vertex 扩展保持独立待选范围。
- 受限管理员密钥、多人风控/在途预占、完整 pinned/live/model_allowlist 目录系统、共享解码 revision/COW 和轻量 quota 查询方案未随诊断加入；当前目录观测/CAS 与纯映射解析器继续使用既有合同。
- PostgreSQL-only、多实例租约及缺少原生平台/插件/视频引擎消费者的修复不适用于当前架构。其余历史遗留以最新评估和选定实施记录为准。
