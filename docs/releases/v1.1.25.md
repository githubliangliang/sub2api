升级与行为变化
==============

1. SQLite：升级增加迁移 229 的单 Key 费用覆盖索引，无新增业务列。索引需要额外磁盘并有构建/写入成本，大库首次升级时间取决于实际数据；升级前保留数据库和配置备份。鉴权快照仍为 21，Ent/Wire 无变化。
2. WS：原生后续轮次容量失败会 1013 关闭；客户端应按关闭结果恢复请求，不能期待网关把已有会话透明搬到另一账号。搜索激活回放只使用可验证的完整历史。
3. Refresh Token：并发复用同一旧令牌只有一次成功，客户端应合并刷新并保存返回的新令牌；失败请求不能继续使用已消费旧令牌换取新 token。
4. 图片：Codex 非流式图片请求保留最终 HTTP 状态，因此首字节可能等待完整生成。反向代理首字节超时需覆盖实际生成时间；验证中较短代理期限确实可返回 504。本版没有操作业务代理或部署配置。
5. 计价：Sonnet 5.5 缓存读 fallback 调整，不追溯改写历史 usage；显式覆盖价优先。价格同步失败继续保留有效旧价格，实际下载正文与 hash 同步发布。
6. UI：Key 的列表 loading 不再等待用量；账号刷新保留旧值直至成功更新。失败时可继续看到已有数据，不将旧值解释为新查询成功，也不增加 Antigravity 强制查询按钮。
7. 资源默认保持 gateway 请求体预算 64MiB、SSE 行 40MiB、队列 8MiB、读写 idle 120 秒、断开后 drain 总限 180 秒及 WS 默认容量系数 1.0。未引入最低 1GiB 的自适应预算；这些配置不等于完整进程内存上限。

- 第二档实施：最终后端全量 unit、embed build、lint 0、五包定向 race 及追加平台/SQLite worker/并发启停检查通过；真实本地 HTTP/WS、SQLite、miniredis 覆盖后续轮次、模型冷却、原子刷新、迁移和排队 usage 结算/dedup。
- 第二档前端：291 文件，2197 通过 / 2 个既有跳过；critical 179 / 2，typecheck、lint、build 通过。真实构建 SPA 和 Chrome 覆盖桌面/390px 移动、慢用量/失败、账号 DOM/配额保留及刷新禁交互；页面 API 为合成拦截。
- 覆盖索引测量：20000 行合成数据增加 868352 字节；同机查询中位 7.398ms→3.128ms，5000 行写入 158.236ms→195.536ms。1GiB/1CPU 临时容器迁移 18.638ms，查询 6.433ms→3.002ms，写入 153.787ms→143.190ms，memory.peak=66850816 字节。写入方向存在噪声，不宣称稳定加速；这些是局部夹具结果，不是生产性能或完整实例内存保证。
- 原子刷新使用真实 miniredis 执行 Lua：8 请求服务层 barrier 仅 1 成功，16 并发直接缓存消费也仅 1 成功。SQLite 审计小任务本地唤醒约 1ms，仍由轮询拾取未通知的到期 retry；不外推实际审计吞吐。
- 以上为已完成实施验收。本次发布另执行后端 unit/Release 同类 integration、前端构建、发布脚本检查、版本解析、静态 embed 构建及实际二进制版本核对，结果见独立 readiness，不将历史 race/浏览器验收说成本次重跑。
- 所有上游响应、账号和页面数据均为本地合成夹具，持久化使用真实临时 SQLite、缓存使用 miniredis；不是供应商在线权限、真实 Codex Desktop 联机或业务实例验收。依赖无升级；历史安全扫描及本次远端检查按实际 SHA 单列，不宣称无安全告警。
