v1.1.23

个人 / 单节点 SQLite 版：新增运维窗口级输出 TPS 分布，修复原生 Claude Fast 请求的日志档位，解决操作日志清理后旧记录重新出现与页面迟到请求覆盖问题。

相对 v1.1.22（ed2340cc5a922ced3e2e408465237f72e8a93579）。产品基线为 765b4c6b0841fb6b9c6b345543bd06c72f25188b；发布准备提交为本 tag 指向的提交，提交内 VERSION 为 1.1.23。
继续使用本 fork 自有 1.1.x 版本号，保持 Go 1.27.3、SQLite 最大迁移 227、SQLite-only、可选单进程 miniredis、simple mode 与 WS 默认容量系数 1.0。

同步上游
========

1) 历史 v0.2.16 评估范围：用户选定 PR #7911 的运维窗口 TPS 余项

   - 实现提交 f333aa5f3aa7a6f6ecc4d1620cbfc47a737e16e3（2026-11-04），来源为完整 PR merge 745ff1d3ca79a7f39520f627f6aa44d778a11580 的第一父到 merge diff。此前已发布日志 TPS，本次补齐用户选定的运维统计部分。
   - 在既有 /admin/ops 普通及全屏页面展示 P5、P10、P50、算术平均值和有效样本数，支持平台、分组、时间窗口筛选及刷新；移动布局与中英文文案同步。
   - 每条样本按 output_tokens × 1000 / duration_ms 计算。分位数对整个选定窗口内仍保留的有效明细排序、连续插值，不平均小时分位数，也不以总 Token / 总耗时替代算术平均值。
   - 排除无正输出/耗时、图片以及 Live/unknown 类型记录；raw、auto、preagg 模式复用相同时间、分组及平台归属筛选，overview 与 snapshot-v2 接口口径一致。
   - 使用 SQLite 窗口函数与线性插值替代上游 PostgreSQL percentile_cont；查询自身设置 2 秒预算，超时降级为统计不可用并保留基础概览，调用方取消或截止继续传播。
   - 空样本显示空值，不伪装成 0 TPS；历史明细已清理时仅依据剩余记录统计，即使聚合数据还存在，也不从聚合结果还原分位数。
   - 这是已选第三档能力的补齐，不是整批上游新版本合入；最新完整上游评估终点仍为 v0.2.19。本轮没有新的上游 release intake。

本仓库自上一 tag 起另外新增
==========================

1) 原生 Claude Fast 日志档位修复（e3f98da7385ca40800eeeb8bb7bea7fe0d571554，2026-11-05）

   - 修复客户端已发送 speed=fast、日志却因缺少服务档位信息而显示 Standard 的缺口。
   - native/OAuth 与 API Key 自动透传路径，在 JSON 和 SSE 场景保留实际最终发送的请求速度，并传递到用量日志构造器。
   - 上游 usage.speed 的明确声明优先；例如请求 fast、上游明确返回 standard 时，日志记录 Standard。流式直接解析和 patch 合并入口均覆盖。
   - 缺失或未知速度不覆盖已观测的有效值，仅有 beta header 不推断 Fast。既有 Codex/OpenAI priority → Fast 与上游声明优先规则回归通过。
   - 本项修正日志分类，不新增 Fast 请求开关、发送行为或价卡，不等同于实现 Fast/Free Fast/Ultrafast 新能力。

2) 操作日志全部清理与异步写入顺序修复（同上提交）

   - 修复数据库清空后，异步队列或已取出的本地批次又写回旧记录的问题。
   - 清理与实际落库使用同一写锁；成功清理后淘汰旧代队列和批次，清理后的新操作继续保留，失败清理不丢弃原队列。
   - Record 保持非阻塞；保留现场 TOTP 要求，以及 admin.audit_log.clear 的同步清理留痕。因此成功清理后仍会看到本次清理操作记录。
   - 前端加入列表请求序号，旧请求的迟到结果或错误不再覆盖清理后的当前查询。
   - 检查状态时显示加载并禁用按钮；未启用 TOTP 时给出系统设置或个人资料入口；验证码限制为六位数字，清理中禁用输入并阻止 Enter/点击重复提交。

3) 完成记录与发布版本对齐

   - 667420d77 回填 TPS 实现提交与验收状态；765b4c6b0 回填日志修复提交与验收状态。TPS OpenSpec 已完成，仍为待归档活动变更。
   - VERSION 从 1.1.22 升至 1.1.23，增加本版详细发布说明与独立发布准备证据，再创建 annotated tag，按 main、v1.1.23 顺序推送。
   - 相对 v1.1.22 没有依赖、SQLite 迁移、Ent/Wire 或数据库 schema 变更。历史来源、旧发布说明及实施验收记录保持原时点内容。

明确未合
========

- 支付、充值、购买/续费、退款、返利及支付提供商专属功能、配置、依赖和迁移继续排除。
- #7043 默认 WS 容量系数 5.0 不采纳，继续保持 1.0。
- 费用趋势、渠道监控 Base URL 路径前缀、Claude 重置 grant、统一图片实际张数计量开关、50 MiB 上传扩围和 Gemini 重试配置仍按需选择。
- Fast/Free Fast/Ultrafast 新能力、Realtime、完整 Grok 429/WS 容量与 exec_scope/抢占机制、动态长上下文/effort 计价及未选新模型/平台不随本次日志修复引入。
- 受限管理员密钥、多人风控/在途预占、完整 pinned/live/model_allowlist 目录系统、共享解码 revision/COW 等仍属于独立范围。
- PostgreSQL-only、多实例租约及缺少平台/插件/视频引擎消费者的修复不适用于当前架构。窗口 TPS 已在本次完成，不再列为未合项；其它遗留状态以原评估和后续用户选定记录为准。
